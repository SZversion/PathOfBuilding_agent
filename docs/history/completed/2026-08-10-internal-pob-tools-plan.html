Internal PoB Tool Layer

Status: Awaiting implementation approval

Branch: feat/pob-agent-architecture

Goal

Expose the already-calculated PoB in-memory state through small, read-only Lua functions that return a consistent Fact Envelope with values, provenance, and optional breakdown data.

In scope

  • Create one internal AgentTool.lua module.
  • Implement get_character_stats(build).
  • Implement get_skill_stats(build, skillIndex).
  • Implement get_projectile_count(build, skillIndex).
  • Implement get_curse_limit(build).
  • Implement explain_stat(build, stat, skillIndex).
  • Reuse AgentSnapshot.lua; do not duplicate PoB calculations.
  • Return calculationVersion, facts, sources, and optional trace.
  • Add focused Lua tests and one external user-build test.

Out of scope

  • Qwen or online model integration.
  • PoB UI changes or a chat window.
  • HTTP, MCP, or any separate server process.
  • Natural-language question routing.
  • PoB calculation formula changes.
  • RAG, prompts, Korean aliases, or new game-rule collection.
  • Bulk analysis or persistent database storage.

Interface contract

get_character_stats(build) -> envelope | nil, error
get_skill_stats(build, skillIndex) -> envelope | nil, error
get_projectile_count(build, skillIndex) -> envelope | nil, error
get_curse_limit(build) -> envelope | nil, error
explain_stat(build, stat, skillIndex) -> envelope | nil, error

envelope = {
  calculationVersion = string,
  facts = table,
  sources = string[],
  trace = table[] -- empty for non-explain tools
}

AgentTool.lua must normalize the existing snapshot shapes into this envelope; it must not expose outputs or skills as the top-level tool contract.

  • get_character_stats returns nil, error when build state is unavailable.
  • get_character_stats.facts is the scalar character output map.
  • get_skill_stats.facts is { skillIndex, name, skillPart, trigger, output }.
  • get_projectile_count.facts is { skillIndex, value }.
  • get_curse_limit.facts is { value }.
  • explain_stat.facts is { stat, value }.
  • get_projectile_count reads activeSkillList[skillIndex].output.ProjectileCount.
  • get_curse_limit reads player.output.EnemyCurseLimit.
  • Missing build state, invalid/non-integer skill indexes, and missing stats return nil, error with the same error convention.

Implementation steps

  1. Add AgentTool.lua with input validation and envelope construction.
  2. Map projectile and curse tools to existing PoB output fields.
  3. Map character and skill tools to scalar snapshot fields.
  4. Delegate explanation calls to AgentSnapshot.explain.
  5. Add self-checks for valid values, missing skill indexes, and missing stats.
  6. Run the external Imported build.xml headless test.

Acceptance criteria

  • No PoB calculation module is modified.
  • Every tool is read-only and returns the same envelope shape.
  • Invalid input returns an explicit error instead of throwing an opaque error.
  • Projectile and curse results expose the exact PoB output keys above.
  • Focused user-build testing is a smoke test: it asserts snapshot creation, skill count, and a non-nil curse value; projectile is non-nil when the fixture has a projectile skill and otherwise reports the documented unavailable state.
