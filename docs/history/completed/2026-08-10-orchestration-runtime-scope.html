Orchestration Runtime Scope

Goal

Execute the deterministic plan produced by agent.orchestration.planner.plan and return structured, inspectable results for one user question.

In scope

  • Validate a planner result and execute its ordered steps.
  • Run search_knowledge through the existing KnowledgeSearch implementation.
  • Accept injected PoB/tool handlers so Lua integration can be added without changing the runtime contract.
  • Return per-step status, result, and error data in deterministic JSON-compatible structures.
  • Provide a small self-check for search success, missing handlers, handler errors, and step ordering.

Out of scope

  • LLM/model calls, prompt generation, RAG synthesis, and natural-language final answers.
  • Launching or embedding LuaJIT/PoB, UI, server, persistence, or network access.
  • Changing the planner, PoB calculation code, or knowledge index format.

Contract

execute(question, plan, search=None, handlers=None) -> {
  "question": string,
  "intent": string,
  "steps": [{"tool": string, "status": "ok"|"unavailable"|"error", "result": any?, "error": string?}]
}

Each injected handler is called as handler(arguments_dict) and returns its plain result. Unknown tools are unavailable; handler exceptions become error. A missing/non-dict arguments value is an error. Execution never raises for malformed plans.
