PoB Mechanism Fact Structure

Status: Approved for implementation

Branch: feat/pob-agent-architecture

Goal

Convert PoB's already-calculated in-memory skill, socket, trigger, item, and breakdown state into a compact, explainable mechanism snapshot.

In scope

  • Add one read-only AgentMechanismTool.lua module.
  • Expose socket groups, gem order, item slot, enabled state, and main-skill indexes from build.skillsTab.socketGroupList.
  • Expose calculated skill metadata, trigger metadata, and scalar output values.
  • Expose available projectile and curse facts through the existing AgentTool.
  • Expose scalar entries from player.breakdown and each active skill's breakdown when present.
  • Attach status = calculated, unavailable, or not_simulated to each derived area.
  • Return the existing Fact Envelope shape and use only Lua standard features.
  • Add one deterministic fake-build self-check and extend the external smoke test.

Out of scope

  • New combat, curse-order, trigger, or damage simulation formulas.
  • Changes to PoB calculation modules or UI.
  • Natural-language routing, model, server, RAG, or database work.
  • Claiming an actual application order when PoB only exposes socket order.
  • Persistent mechanism snapshots or a new serialization format.

Contract

get_mechanism_snapshot(build) -> envelope | nil, error

envelope = {
  calculationVersion = string,
  facts = {
    socketGroups = table[],
    skills = table[],
    projectile = table,
    curse = table,
    breakdown = table
  },
  sources = string[],
  trace = table[]
}
  • Every list preserves PoB order.
  • Unavailable optional data is represented as { status = "unavailable" }.
  • Information that would require a new simulator is represented as { status = "not_simulated" }.
  • Missing PoB calculation state returns nil, error.

Acceptance criteria

  • No PoB calculation source file changes.
  • The fake self-check verifies socket/gem order, trigger metadata, calculated values, and status markers.
  • The real user-build smoke test prints mechanism counts and succeeds when optional values are unavailable.
