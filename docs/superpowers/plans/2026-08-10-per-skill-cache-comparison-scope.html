PoB Per-Skill Cache Comparison

Status: Approved for implementation

Branch: feat/pob-agent-architecture

Goal

Expose the individual skill calculation cached by PoB and compare a support gem enabled versus disabled, including projectile count, chain count, remaining chains, and DPS.

In scope

  • Read per-skill results from GlobalCache.cachedData.MAIN/CALCS[*].Env.player.mainSkill.output.
  • Use PoB's existing cacheSkillUUID(skill, env) and cache entries; do not copy or reimplement formulas.
  • Add a Tool that compares one named support gem in one named skill group with enabled=true and enabled=false.
  • For each state expose ProjectileCount, Chain, ChainMax, ChainRemaining, ChainMaxString, and TotalDPS when present.
  • Return field-level availability and numeric/string deltas where both states are numeric.
  • Restore the original Skill Set, main socket group, calculation input, support enabled flag, and rebuild the original context after success or error.
  • Add fake and real-build tests using the existing LuaJIT headless runner.

Out of scope

  • New damage, projectile, or chain formulas.
  • Changing PoB calculation modules.
  • Multiple support gems or combinatorial build optimization.
  • UI, model, server, routing, RAG, or database work.
  • Persisting modified build state.

Contract

compare_support_effect(build, skillSetSelector, skillName, supportName)
  -> envelope | nil, error

facts = {
  skillSet = { id, title },
  skill = { name, socketGroup },
  support = { name, enabledBefore },
  enabled = { status, output },
  disabled = { status, output },
  delta = { ProjectileCount, Chain, ChainMax, ChainRemaining, TotalDPS }
}

Acceptance criteria

  • PoB cache output is read without formula duplication.
  • Greater Volley comparison reports an increased/decreased projectile and chain result when PoB provides both states.
  • Original state is restored on success and error.
  • Unavailable outputs are explicit and never replaced with guessed values.
