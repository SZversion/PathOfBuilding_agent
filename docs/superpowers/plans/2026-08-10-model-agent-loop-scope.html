Model Agent Loop Scope

Goal

Connect a chat model to the existing orchestration runtime using a two-call tool loop.

In scope

  1. Ask the model for a JSON-only Tool plan.
  2. Validate the plan against a small allowlist and execute it through the existing runtime.
  3. Send the original question, validated plan, and Tool results back to the model for the final answer.
  4. Provide an OpenAI-compatible HTTP client usable with local llama.cpp servers or online endpoints.

Out of scope

  • Downloading or embedding model weights.
  • UI, streaming, multi-turn memory, retries, or autonomous loops.
  • Allowing model-generated tools outside the registered handler map.

Safety contract

Allowed Tools are search_knowledge, get_projectile_count, get_curse_limit, get_elemental_penetration, get_socket_order, get_skill_chain, compare_support_effect, and explain_damage_change. A plan has at most 8 steps; every step has a string Tool and object arguments; unknown or duplicate Tools are rejected. Invalid plans return {"status":"plan_error","error":string} and execute no Tool.

Model contract

model.chat(messages) -> string. The first response is a JSON object containing steps; the second response is the final answer text. The OpenAI-compatible client posts to {endpoint}/chat/completions with Authorization: Bearer {api_key} when configured, a timeout, and reads choices[0].message.content. The final prompt requires the model not to invent missing values.
