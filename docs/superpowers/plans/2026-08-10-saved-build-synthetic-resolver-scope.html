Saved Build Synthetic Resolver Scope

Goal

Resolve skills only from a saved XML build after PoB has generated its synthetic socket groups.

In scope

  • Require an existing readable XML path in the Python/Lua bridge; do not expose GUI-memory build access.
  • After XML load and calculation, scan build.skillsTab.socketGroupList.
  • Include socketed, item-granted, tree-granted, and triggered groups using source, sourceItem, sourceNode, and gem.fromItem.
  • Use displayGemList when present so item-granted skills include same-slot support gems; fall back to gemList.
  • Return source, slot, group index, skill name, support names, link count, enabled state, and active skill index.

Out of scope

  • Reading unsaved PoB GUI memory, reverse-engineering process memory, or changing PoB UI.
  • Manually reconstructing item-granted support behavior outside PoB's generated groups.

Deterministic provenance

Classify in this precedence order: sourceItem or gem.fromItem → item_granted; else sourceNode → tree_granted; else group.source → generated; else socketed. sourceItem is summarized as {name?,baseName?}; sourceNode is returned as a scalar ID/string. If more than one group matches the skill name after selector filtering, return nil,error with an ambiguity message.

Read displayGemList when present, otherwise gemList. The first active gem is the skill; remaining entries whose granted effect is a support are support names. linkCount is the number of entries in this effective list.

Contract

find_skill(build, selector, name) -> {
  skillSet, socketGroup, skillIndex, name, sourceType, sourceItem, sourceNode,
  slot, supports, linkCount, enabled
} | nil,error
