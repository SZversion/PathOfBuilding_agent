# Korean Bitmap Font Support

## Goal

Render Korean text throughout the Path of Building Community UI using bitmap glyphs, including chat messages and user input, without relying on fonts installed on the user's computer.

## Current behavior

- `SimpleGraphic` converts rendered strings to Unicode code points, but its `.tgf` font metadata and renderer currently index glyphs as an ASCII-only table of 128 entries.
- Missing code points are rendered as visible `U+XXXX` placeholders.
- Font atlases are generated by the separate `PathOfBuilding-FontGenerator` utility and packaged by this repository.
- The PoB workspace contains the compiled `SimpleGraphic.dll` and runtime font assets, but not the renderer or generator source.

## Proposed design

- Bundle a Korean font with PoB so output is consistent across Windows installations and independent of installed fonts. Use Noto Sans CJK KR (SIL Open Font License 1.1) unless the renderer build investigation finds a compatibility issue.
- Rasterize Korean glyphs into bitmap atlas pages and cache glyphs by Unicode code point and requested pixel height. Rendering continues to use bitmap textures; no system-font fallback is used.
- Keep the existing PoB bitmap fonts for characters they already contain. Resolve missing glyphs through the bundled Korean bitmap cache.
- Cover the full Hangul syllable block, modern Hangul jamo, and standard Korean punctuation. Unsupported scripts such as Hanja keep the existing visible `U+XXXX` placeholder behavior.
- Share the Korean bitmap cache across existing PoB font faces while preserving their existing ASCII appearance. The Korean fallback face uses regular and bold weights where available.
- Update the SimpleGraphic renderer and the font metadata/generation path, build the Windows runtime DLL, add the bundled font/license and required runtime data, and update the PoB manifest hashes.
- Preserve UTF-8 input, drawing, width measurement, wrapping, and cursor-index behavior across the UI.

## Compatibility and resource constraints

- Existing ASCII atlas entries and visual output must remain unchanged.
- The cache must have a bounded memory footprint and support atlas page growth or eviction without invalidating glyphs referenced in the current draw frame.
- If font loading or glyph rasterization fails, retain the existing tofu placeholder for that code point and keep the UI running.
- The font license and notices must ship with the application.

## Validation

- Manually inspect Korean output at small and large UI text sizes, including mixed ASCII/Korean, punctuation, multiline text, and cursor placement.
- Confirm the packaged runtime loads without an installed Korean font and that missing unsupported characters still show the existing placeholder.
- Do not run the test suite unless separately requested.

## Scope exclusions

- Korean translation of PoB interface labels.
- Hanja and unrelated scripts absent from the bundled Korean font subset.
- Changes to the agent server or model API; this is a renderer and font asset change.
